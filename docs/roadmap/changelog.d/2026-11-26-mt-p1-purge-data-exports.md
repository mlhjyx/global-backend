title: "feat(workspace,data-exports): 补齐整工作空间物理清理工作流与异步租户数据导出"
---

- 起因：MT-P1 商业化多租户离网清理与数据可携性缺少两部分核心后端能力：(1) `gain-saas` 离网注销或运营封禁清理时缺少引擎侧 `POST/GET /api/v1/internal/workspaces/:id/purge` 与全链路物理擦除（覆盖 ~145 张租户表含 5 组不可变触发器表、3 个私有 MinIO 桶、`http-throttle`/工作空间 Redis 键及运行中 Temporal 工作流，且须保持未引用外的跨租户共享 legacy 对象安全）；(2) 租户缺少异步数据导出与鉴权流式下载代理（`POST/GET /api/v1/data-exports`、`GET /api/v1/data-exports/:exportId/download`）。
- 改动：
  1. **Schema、迁移与治理基线**：在 `packages/db/prisma/schema.prisma` 新增 `DataExportJob`、`WorkspacePurgeReceipt`（无 FK 指向 `workspace`，清理后保留非 PII 审计回执）与 `WorkspacePurgeTxFence`（`owner_only`）；新增迁移 `20261126080000_workspace_purge_and_data_export`，开启 `FORCE RLS` 与租户策略，更新 5 个不可变触发器函数以在活动事务围栏下精确放行 `DELETE`（保持 `discovery_company_materialization_activation` 与独立删改永拒），提供 `app_user` 可调用的 M4 合规 `SECURITY DEFINER` RPC（`begin_workspace_purge_v1`、`mark_workspace_purge_running_v1`、`snapshot_workspace_purge_targets_v1`、`purge_workspace_tenant_data_v1`、`complete_workspace_purge_v1`、`fail_workspace_purge_v1`）；同步更新 `app-user-table-privileges.json`、`g5-rls-catalog.json` 与 Copy fixed-source 指纹及治理回执。
  2. **整工作空间物理离网清理**：新增 `WorkspacePurgeServiceTokenGuard`（`WORKSPACE_PURGE_INTERNAL_SERVICE_TOKEN`、`x-service-token` 常量时间校验、无 loopback 限制）、`WorkspacePurgeInternalController`、`WorkspacePurgeService`、`workspace-purge-redis.ts`、为 `SellerDocumentsStorage` 与 `DataExportStorage` 补齐 `deletePrefix`，并实现 `global-worker` 侧 `workspacePurgeWorkflow` 与 `workspace-purge.activities.ts`（取消运行中工作流、物理擦除全部租户数据库行含 `identity_link`/`field_evidence`/`sanctions_screening_result` 并置空平台表 `source_channel_run.triggered_by_workspace_id`、清理 `global-seller-documents` / `DATA_EXPORT_S3_BUCKET` / `global-site-builder` / `global-operation-artifacts` 个人数据对象及 Redis 键；缺失 `workspace` 行时安全作为空库清理收尾）。
  3. **异步租户数据导出与流式下载**：新增 `apps/api/src/data-exports/`（`DataExportsModule`、`DataExportsController`、`DataExportsService`、`DataExportStorage`、`data-exports.formatter.ts`、`zip-writer.ts`）、`infra/minio/seller-documents-lifecycle.json` `data-export-ttl` 1 天标签规则，以及 `dataExportWorkflow` / `data-export.activities.ts`；支持 `leads`/`companies`/`contacts`/`outreach`/`full_archive` × `csv`/`jsonl`（含 CWE-1236 CSV 公式中和、零外部依赖 `node:zlib` ZIP 打包、`withWorkspace` + `piiExtension` 自动解密 PII、每空间 2 并发 / 24 小时 10 次配额、24 小时 TTL 与 `StreamableFile` 流式下载）；同步更新 OpenAPI 契约、`operation-descriptions.ts`、`controller-authz.spec.ts`、`g16-module-boundaries.json` 及 `.github/workflows/ci.yml`（G15）。
- 测试：已在隔离 worktree `/global/.agy-worktrees/backend/mt-p1-purge-data-exports` 完成构建、OpenAPI 导出、lint、单测与合同测试、governance/docs/copy-fixed-source/gitleaks 门禁，以及一次性 PG16 容器与本地 MinIO/Redis 集成测试（含新增 `workspace-purge.postgres.spec.ts` 与 `data-exports.postgres.spec.ts`）。
- 未做：已本地验证通过并提交至 `feat/mt-p1-purge-data-exports`，按编排要求尚未推送远程、创建或合并 PR，也未部署至现网。
