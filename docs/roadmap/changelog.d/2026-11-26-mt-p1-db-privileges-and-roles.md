title: "feat(db): 收紧运行时非超级用户分权角色并撤销 app_user 16 张平台表写权限"
---

- 起因：MT-P1 最小权限加固收口两项遗留风险：(A) 5 个运行时进程/服务（`OutboxRelayService`、`DataRightsService`、`MemoryEpisodeConsumer`、`temporal/worker.ts`、`temporal/platform-worker.ts`）仍直接读取 `process.env.DATABASE_URL`（表 owner / superuser 凭据），可绕过 `FORCE ROW LEVEL SECURITY`；(B) `app_user` 在 16 张未启 RLS 平台表上仍持有 `INSERT`/`UPDATE`/`DELETE` 权限，任意 API 或租户会话连接均可直改平台元数据与抑制表。
- 改动：
  1. **剥离运行时 `DATABASE_URL` 与部署期目录初始化 CLI**：新增 `apps/api/scripts/seed-platform-catalogs.mts`（及 `@global/api` `seed:platform-catalogs`）承载迁移/部署期目录初始化（拒绝 `app_user`）；新增 `apps/api/src/runtime/platform-catalog-verification.ts`（导出 `DEFAULT_EXPECTED_PROVIDER_KEYS` 供 `OutboxRelayService` 与 `worker.ts` 做仅 `SELECT` 校验，移除不存在的 `"sandbox"` 键）替代启动写库；新增向后兼容迁移 `packages/db/prisma/migrations/20261126010000_runtime_scoped_principals/migration.sql` 创建 `runtime_outbox_relay_worker`、`runtime_memory_outbox_reader`、`runtime_customer_worker_ops`（`NOSUPERUSER NOBYPASSRLS`；`worker_ops` 仅保留 `source_signal` 只读 `SELECT` 并禁止写 `signal_ingest`/`source_signal`）并扩展 `execution_budget_platform_writer` 与 `public.list_platform_workspace_ids_v1()`；新增 `apps/api/src/runtime/scoped-database-principal.ts`（含 `scopedDatabaseTargetsAppDatabase`）校验 `pg_roles`/`session_user`，切线全部 5 个运行时入口及 `infra/backend-runtime.compose.yml`（清空 `DATABASE_URL: ""`）、`runtime-admission.ts`（`RUNTIME_OWNER_DATABASE_URL_FORBIDDEN`、目标库一致性与 API 可选 `EXECUTION_BUDGET_PLATFORM_WRITER_DATABASE_URL` 校验）、`development-candidate.ts`（拒绝 `postgres`）与 `infra/postgres/{provision,verify}-runtime-service-principals.sh`；在 `createContactReverifyActivities` 传入 `prisma`（`app_user`）供 `checkProviderGates` / `withSmtpProbeFallback` 只读 `source_policy`，消除 `workerOpsDb` `42501`；移除 `SignalIngestService` 的 `signalWriter` 旁路（`externalIntentSweepWorkflow` 写路径统一要求 `platformWriter`）。
  2. **撤销 `app_user` 在 16 张无 RLS 平台表的写权限与调用方切线**：新增迁移 `packages/db/prisma/migrations/20261126020000_revoke_app_user_platform_table_writes/migration.sql` 撤销 `app_user` 在全部 16 张表的 `INSERT`/`UPDATE`/`DELETE`（保留 `SELECT`），扩展 `execution_budget_platform_writer` 对平台/管理表的写权限，新增 4 个 `SECURITY DEFINER` RPC（`record_patent_inventor_tombstones_v1`、`purge_patent_inventor_cache_by_keys_v1`、`enqueue_patent_lookup_v1`、`upsert_term_alias_v1`，均固定 `SET search_path = pg_catalog, public, pg_temp`；前两者强制 `app.current_workspace_id`、`^bi:v1:[0-9a-f]{64}$` 盲键格式与 `256` 批上限，`upsert_term_alias_v1` 强制 `app.current_workspace_id` 与 `WHERE public."term_alias"."source" = 'llm'` 保护 `'seed'`/`'manual'` 行）；在 `execution-budget-platform-writer.database.ts`（`createExecutionBudgetPlatformWriterClient` 与 `assertExecutionBudgetPlatformWriterPrincipal`）、`channel-platform-writer.ts`、`outreach-dnc.service.ts` 对 `EXECUTION_BUDGET_PLATFORM_WRITER_DATABASE_URL` 实施 URL 与数据库连接主体双重 fail-closed 校验并在 `apps/api/.env.example` 说明；完成 `deletion.activities`（按 256 键分批）、`patent-inventor-cache`、`taxonomy-resolver`、`channels/*`、`outreach-dnc`、`signal-ingest`、`acquisition`、`intent`、`external-intent.activities`、`platform-worker` 及运维脚本调用切线；同步更新 `docs/governance/{app-user,platform-writer}-table-privileges.json`、`docs/governance/ci-baselines/g16-module-boundaries.json`（补充 `memory -> runtime`）及 `.github/workflows/ci.yml`（运行 `scoped-runtime-principals.postgres.spec.ts`）。
  3. **基线同步**：运行 `copy-fixed-source-impact.mjs --write-eligibility` 更新 `copy-runtime-eligibility.json` 与 `docs/implementation-records/copy-fixed-source-impact-governance.md`（因新增 `apps/api/package.json` 脚本引起指纹重算，Scope 保持 `STALE_HOLD`）。
