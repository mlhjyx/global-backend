- 起因：多租户安全审计（MT-P2 / M8）确认三处加密与隐私隔离短板：(1) `pii-crypto.ts` 使用单一全局 `PII_ENCRYPTION_KEY` 且未混入 `workspaceId`，跨租户同明文产生逐字节相同的密文与盲索引，且不支持零停机轮换，同时默认对非密文值静默明文回退；(2) `outreach_global_suppression` 以无盐纯 `SHA-256(email)` 落库，易受离线字典探测；(3) `source_channel_record` 的联系人四列（`contact_name` / `contact_title` / `email` / `phone`）仍以 `VARCHAR` 明文存储。
- 改动：
  1. 升级 `apps/api/src/compliance/pii-crypto.ts` 与 `pii-crypto.extension.ts` 为 `enc:v2:<keyId>:<iv>:<tag>:<ct>` / `bi:v2:<keyId>:<hex64>`：由 `PII_KEYRING_JSON` 持有 KEK，按 `ws:<workspaceId>` 或 `platform:<scope>` 经 HKDF-SHA256 派生每作用域 DEK / IV_KEY / BI_KEY 并绑定 `pii:v2:<scope>:<purpose>` 作为 AES-256-GCM AAD；支持多密钥零停机轮换与可选遗留 `PII_ENCRYPTION_KEY`（`enc:v1:` / `bi:v1:`）兼容解密及候选集检索；默认关闭静默明文回退（`PII_PLAINTEXT_FALLBACK_FORBIDDEN`），仅允许显式 `allowLegacyPlaintext: true` 或迁移窗口 `PII_ALLOW_LEGACY_PLAINTEXT_READ=true` 读取遗留明文；同步更新全部租户/平台 PII 调用点与 `runtime-admission.ts` 启动校验。
  2. 新增 `apps/api/src/compliance/pii-reencryption.ts`（收敛 `contact_point` 写入至 `discovery/contact-point-writer.ts` 单一写入器，碰撞去重先删弱行再原地换密文/迁联系人以保住四态列与 `contact_point_verification_event` 账本，平台枚举与平台表回填走 `execution_budget_platform_writer`），并在 `contact-point-writer.ts` 与 `email-guess-persist.ts` 补齐密钥轮换窗口多密钥候选集检索防重复建点；升级 `apps/api/scripts/backfill-pii-encryption.mts` 支持按租户 RLS 与平台作用域幂等重加密及盲索引升级。
  3. 升级 `apps/api/src/outreach/outreach-dnc.service.ts` 以 `HMAC-SHA256(OUTREACH_DNC_HMAC_PEPPER, 'outreach-dnc:v1:' + canonical)` 持久化 `outreach_global_suppression.email_hash`，支持 `OUTREACH_DNC_HMAC_RETIRED_PEPPERS` 平滑轮换并保持 HTTP 响应 `sha256` 关联键兼容 `gain-saas`；新增幂等重哈希运维脚本 `apps/api/scripts/rehash-outreach-global-suppression.mts`（正常重哈希保持 `platform_writer` append-only，`--prune-legacy` 才需迁移期拥有者连接）。
  4. 新增两份数据库迁移 `20261126090000_pii_crypto_v2_blind_keys`（放宽 `contact_point_domain_blind_key_check` 与 M4 专利发明人擦除/墓碑 RPC 正则同时接受 `bi:v1:` 与 `bi:v2:<keyId>:`）及 `20261126100000_encrypt_source_channel_record_pii`（放宽 `source_channel_record` 四列联系人字段为 `TEXT`）；更新 `channel-records.ts`、`channel-records.prisma.ts` 与 `channel.service.ts` 在写入前随机 IV 加密、读路径解密，并同步 `packages/contracts/openapi/openapi.json`、`docs/governance/ci-baselines/g16-module-boundaries.json` 及 Copy fixed-source eligibility receipt。
- 测试：已在隔离一次性 PG16 容器实测跑通 `prisma migrate deploy`、`prisma-drift-gate`、`migration-integrity-gate`（15/15）、`rls-catalog-gate`（196 表）、`pii-crypto-v2.postgres.spec.ts`（3/3，含四态碰撞保留事件账与轮换窗口防重）及 8 个受影响 PG16 套件（`scoped-runtime-principals`、`app-user-table-privileges`、`governance-table-privileges`、`raw-sql-parameter-types`、`security-definer-search-path`、`contact-point-four-state`、`data-exports`、`deletion-company-erasure`，51/51 全过）；已通过 `@global/db generate`、`@global/contracts build`、`@global/api build`、`pnpm contracts:lint`、全部新增与受影响单测以及全套治理与密钥快门（`governance:verify`、`docs:verify`、`copy-fixed-source-impact`、`governance-document-drift`、`governance-changelog-fragments`、`gitleaks`）；本机 Node 为 `v22.23.1`，两项 Astro 7.4.7 渲染测试因宿主机 Node `<22.23.4` 交由 CI 验证。
