## 3. 承重假设（可证伪）

1. **A1：Pack 是数据，不是执行器。** Pack 解析只产出「有序规则 + 内容片段 + 来源」，由解释器（确定性）与提示渲染器消费；任何 Pack 都不能新增工具、放宽 ToolBroker 白名单或跳过审批。证伪：任一 Pack 字段能让技能调用白名单外的工具 → 设计错误。
2. **A2：优先级 + forbid 不可放宽足以表达 PRD §7.11.7。** 冲突裁决 = 按固定优先级合并；高层 `forbid` 被低层 `permit` 触碰即冲突（发布时拒绝；解析时记录并保持 forbid）。证伪：出现无法用该模型表达的合法规则组合。
3. **A3：策略注入只作用于 S1 技能（新 service 技能 + 导入 A 档），不改 S0 三技能的输入。** 这样 S1 的提示/行为变化不会打破 S0「零行为变化」的验收。若未来要让存量技能消费 Pack，另立设计（需重新评估零行为变化基线）。
4. **A4：service-kind 技能不需要模型调用。** 制裁筛查与 Incoterms 计算都是确定性函数；引入 `service` 技能类型（闭集 handler 注册表）比「先用模型包装确定性逻辑」更可测、更便宜、更可审计。
5. **A5：CI 无模型密钥，Golden Set 必须分层。** 阻断层用确定性断言与渲染快照；模型实测由运营在发布前触发（引擎 ops 端点），写入不可变回执；发布门校验回执的（技能/Pack 版本摘要 + 评测清单摘要 + 模型策略）完全匹配。
6. **A6：Pack 版本漂移与快照不变式可复用 S0 机制。** DB 行的 manifest 摘要与当前构建目录不一致 → fail-closed；快照内容寻址、append-only。证伪：DB 与目录不同步会静默降级。

## 5. Pack 体系 v1

### 5.1 四类 Pack Schema（`apps/api/src/skills/packs/schemas/`）

共同信封（四类共用，JSON Schema draft 2020-12）：

```jsonc
{
  "packKey": "compliance.eu_dual_use_screen",   // 点分小写
  "packType": "compliance",                      // 四类之一（v1 只启用这四类）
  "version": "1.0.0",
  "title": "…",
  "description": "…",                             // ≤1024
  "priorityClass": "hard_rules|enterprise|compliance|market|industry|growth_motion|channel_data_content_expert|campaign",
  "tags": { "industries": [], "markets": [], "motions": [] },  // 选择器
  "owner": "OWN-…",
  "license": "Proprietary|Apache-2.0|MIT",
  "notice": "…",                                  // 导入内容必须带来源与改动说明
  "contentPath": "PACK.md",                       // 内容片段（≤2k 字，渲染上限见 §5.4）
  "rules": [ /* 由 packType 的 schema 定义 */ ],
  "sources": [ { "label": "…", "url": "…", "retrievedAt": "YYYY-MM-DD" } ],
  "exitPlan": "…"
}
```

按类型的 `rules[]` 最小形状：

| 类型 | 规则形状（v1 最小） |
| --- | --- |
| Compliance | `{ id, effect: "forbid"|"require_approval"|"mask"|"limit", appliesTo: { skills?: [key], tools?: [toolId], phases?: ["understand"|"qualify"|"create"…] }, condition?: { field, op, value }, rationale, sources[] }` |
| Data Source | `{ id, sourceId, category, allowedUse: ["discovery"|"enrichment"|"research"], license, piiClass, rateLimit?, approval: "none"|"ops" }`（只声明**允许的数据源与用途**，真正执行仍走 ToolBroker + source_policy） |
| Growth Motion | `{ id, motion, stage, playbook: [{ step, guidance }], kpis[], guardrails[] }` |
| Industry | `{ id, taxonomy: { scheme, codes[] }, buyerRoles[], terminology[], regulations[{ jurisdiction, note }] }` |

校验分三层：① JSON Schema（结构）；② 语义（key/version 唯一、引用存在、内容长度、sources 非空、导入包必须有 notice）；③ 冲突模拟（在样本上下文上解析，禁止低优先级 `permit` 覆盖高优先级 `forbid` 的组合——命中即发布拒绝）。

### 5.2 优先级与冲突裁决（PRD §7.11.7）

优先级（高→低，固定不可配置）：

```
Legal/Platform Hard Rules > Enterprise Mandatory > Compliance > Market > Industry
> Growth Motion > Channel/Data/Content/Expert > Campaign Override > AI Recommendation
```

裁决规则（确定性、可测试）：

1. 参与解析的包按 `priorityClass` 排序；同层按 `packKey` 字典序（稳定）。
2. 合并 `rules`：同 `(appliesTo, target)` 上的 `effect` 冲突时高层胜；低层被拒项写入快照 `rejected[]`（含原因），不静默丢弃。
3. `forbid` 是吸收态：任何低层 `permit`/`require_approval` 不能移除高层 `forbid`；只在低层新增更严格约束（例：高层 forbid + 低层 require_approval 仍为 forbid）。
4. Campaign Override（M2 输入）与 AI Recommendation 在 v1 只保留位置（枚举与校验），不产生真实来源。

### 5.3 Pack 内容目录（v1 种子）

- 首版内置：`compliance.eu_dual_use_screen`（合规：双用途/制裁相关人工复核提示，规则 forbid/require_approval 示例）、`data_source.public_web_only`（数据源：公开网页 + 官方名录用途边界）、`growth_motion.dach_distributor`（动作包：DACH 分销商获客检查单）、`industry.metal_fabrication`（行业词表/买家角色）。
- C 档 3 个第三方技能作为**内容包**（不执行）：`growth_motion.competitive_intelligence`、`growth_motion.customer_research`、`growth_motion.pricing` —— 以去营销化摘要 + 来源引用进入 `PACK.md`，`notice` 保留 SPDX 与上游 commit。（v1 只启用四类 Schema，`market` 不在其中；三者为 Go-to-market 内容，按 `growth_motion` 类型落地。）
- 内容包与技能包同走 `skills:generate` 生成目录；种子注册为平台默认启用（它们是规则/内容，不改变 S0 技能输入——见 A3）。

### 5.4 解析与策略简报（`pack-resolver.ts` / `strategy-brief.ts`）

- 输入：`workspaceId` + 解析上下文 `{ skillKey, industries?, markets?, motions?, campaign? }`（v1 由调用方显式给出；M2.1 规划器作为未来调用方）。
- 选择：平台启用且（标签匹配或通用）的 Pack；workspace 覆盖优先（disable 则剔除；canary 白名单只影响实验版本，§7.3）。
- 输出：`ResolvedStrategy` = 有序规则集 + 内容片段列表 + `descriptor`（含每个 Pack 的 `packKey/version/manifestDigest`、技能 descriptor、`modelPolicy`、渲染摘要 `strategyDigest`）。
- 策略简报：确定性模板渲染，≤2000 字，按优先级顺序列「硬约束 → 合规 → 行业/市场 → 动作 → 来源」；每条引用带 packKey@version；**不做自由文本生成**。
- 快照：`strategy_resolution_snapshot` 内容寻址（`descriptor_digest` 唯一），append-only；与 S0 的 `skill_resolution_snapshot` 并存（技能级 vs 策略级）。
- fail-closed：包版本与构建目录不一致、规则 schema 不合法、冲突未裁决 → 该次解析失败（不执行技能）。

## 6. 技能运行时扩展与两个新技能 + 导入技能

### 6.1 skill-kind 扩展（服务型技能）

- `metadata.platform.skill-kind`：`model_task`（默认，S0 行为不变）| `service`。
- service 技能：必须声明 `platform.service-handler`（闭集：`sanctions.screen.v1`、`quoting.incoterms.v1`）；`allowed-tools` 必须为空；`human-gate` 与 `risk` 取自 handler 定义并校验一致；不绑定 `task-contract*`。
- 执行分派：`executeSkill` 按 descriptor.skillKind 路由——`model_task` → 既有 `executeSkillWithRuntime`（含 Pack 策略注入后的输入，仅 S1 技能）；`service` → `executeServiceSkill(handlerId, input, context)`：纯函数调用、无模型、无工具；输出过 schema 校验；不写 ai_trace（记录结构化日志与快照）。
- 租户默认：`tenant-default: disabled` 的技能，DB resolver 在「平台 ACTIVE 且无 workspace 覆盖行」时抛新增错误码 `SKILL_TENANT_NOT_ENABLED`（S0 技能的该字段为 `enabled`，语义不变）；显式覆盖 `enabled=true` 才可用。
- 负向：未知 handler、service 技能声明工具、model 技能缺 task 绑定 → 启动/校验即失败。

### 6.2 `compliance.sanctions_screen`（service · L1）

- Handler：`sanctions.screen.v1`，持有 `SanctionsScreeningService`（进程内索引）+ Prisma。
- 输入：`{ companyName, country?, threshold?, opts? }`；输出：`{ status: clear|potential_match|not_screened, matches[]（externalId/sourceKey/matchedName/score/countryMatch/listVersion）, listVersions{} }`——与既有 `ScreenResult` 同构，附 `algorithmVersion`。
- 约束：只读；不返回个人数据（既有摄取层已剔除个人条目）；`not_screened` 诚实返回（源未启用）；不产文件/不发送；L1 建议 + `humanGate=false`（无对外动作）。
- Golden Set：确定性用例（已知实体的 clear/match/阈值边界/空索引 not_screened），CI 可全跑。

### 6.3 `quoting.incoterms_quote`（service · L1）

- Handler：`quoting.incoterms.v1`（纯函数，`decimal` 计算；无浮点误差累积）。
- 输入：`{ incoterm: EXW|FOB|CFR|CIF|DDP, unitPrice, quantity, currency, exchangeRate?（仅当报价币 ≠ 成本币，必须显式提供）, costLines: [{ kind: goods|packaging|inland_freight|ocean_freight|insurance|duty|other, amount, currency }], marginPct? }`。
- 输出：按 Incoterms 2020 的分界计算 `{ incoterm, breakdown[], totalUnitPrice, totalAmount, currency, assumptions[], warnings[] }`；每条含公式版本 `formulaVersion: incoterms-2020/v1` 与输入摘要；`humanGate=true`（人工确认后可用）。
- 红线：**不生成 PI/CI/PL/任何对外单据**；无外部汇率查询（v1 汇率必须输入）；不做税务法律意见（warnings 声明）。
- Golden Set：确定性数学用例（5 个 Incoterm × 边界：零运费、缺汇率、DDP 关税、负毛利拒绝、跨币种），精确断言。
- **实现偏离记录（S1-4 落地时，2026-11-08 复审后定稿）**：① 以必填 `goods` 成本行取代 `unitPrice` 输入（单一价格无法表达分项成本与术语分界）；② `decimal` 以 BigInt 分为单位自实现（不引入依赖，十进制四舍五入，换算与加价整数域完成）；③ `marginPct` 语义为成本加价（markup），总额取精确值、单价四舍五入到分；④ `exchangeRate` 只覆盖一种外币，成本行含多种外币时拒绝；⑤ 制裁筛查 `threshold ∈ (0,1]`，归一化后无可比 token 的名字返回 `not_screened`，命中 >50 条时以 `truncated` 标记；⑥ 制裁技能的 CI 确定性用例用真实匹配引擎（`buildSanctionsIndex`+`screenName`）搭内存索引执行，不使用恒返回值假依赖。

## 7. Pack Studio（引擎 ops API v1）

### 7.1 数据模型（迁移 `2026…_pack_v1`，全部 FORCE RLS / append-only 按列标注）

| 表 | 作用 | 授权（app_user） |
| --- | --- | --- |
| `pack_package` | 平台目录：pack_key/pack_type/status/active_version_id | SELECT + 列级 UPDATE（status/active_version_id/updated_at） |
| `pack_draft` | 草稿（可变）：manifest JSONB/校验报告/updated_by | SELECT/INSERT/UPDATE/DELETE（草稿可弃） |
| `pack_version` | 发布版本（**append-only 不可变**）：manifest/digests/schema_version/published_by | SELECT |
| `pack_activation` | 生效日志（append-only）：package/version/scope(platform|workspace)/canary/activated_by | SELECT/INSERT |
| `pack_enablement` | workspace 启停覆盖（enabled/reason） | SELECT/INSERT/UPDATE/DELETE（本空间） |
| `eval_receipt` | 评测回执（append-only）：subject_kind(skill|pack)/subject_key/version_digest/eval_manifest_digest/tier/case counts/model/costMicros/passed/run_by | SELECT/INSERT |
| `strategy_resolution_snapshot` | 策略解析快照（append-only，内容寻址） | SELECT/INSERT（禁 UPDATE/DELETE） |

平台行（workspace_id IS NULL）跨空间可读，租户表按 `current_workspace_id()` 隔离；与 S0 表同模式。

### 7.2 端点（`@RequireScopes('ops:read'|'ops:write')`）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/packs` | 目录 + 当前生效版本 + 灰度/启用概况 |
| GET | `/api/v1/packs/:packKey` | 详情（版本历史、草稿、回执、激活日志） |
| POST | `/api/v1/packs` | 新建目录 + 首个草稿（type/key 校验） |
| POST | `/api/v1/packs/:packKey/drafts` | 从版本/空草稿派生新草稿 |
| PATCH | `/api/v1/packs/:packKey/drafts/:draftId` | 编辑 manifest/内容 |
| POST | `/api/v1/packs/:packKey/drafts/:draftId/validate` | schema + 语义 + 冲突模拟；返回 issues（零模型） |
| POST | `/api/v1/packs/:packKey/drafts/:draftId/dry-run` | 在样本上下文解析并渲染策略简报 + 与当前生效版本差异（零模型） |
| POST | `/api/v1/packs/:packKey/drafts/:draftId/eval` | 运行 Golden Set（模型层可选；有成本上限；写 `eval_receipt`） |
| POST | `/api/v1/packs/:packKey/drafts/:draftId/publish` | 发布（要求 validate 通过 + 与摘要匹配的有效 eval 回执）；可带 `canaryWorkspaces[]` |
| POST | `/api/v1/packs/:packKey/activate` | 平台默认激活某已发布版本（回滚 = 激活旧版本） |
| PUT/DELETE | `/api/v1/packs/:packKey/workspaces/:workspaceId` | workspace 启停/灰度覆盖 |

技能侧同构的最小入口：`POST /api/v1/skills/:skillKey/evals`（运行 Golden Set 并写回执；skills 的发布沿用 S0 seed/版本机制，回执作为发布证据）；`GET /api/v1/skills/:skillKey/evals` 读回执。

### 7.3 版本与灰度语义

- 草稿可变；`validate` 通过不改变生效；`publish` 创建不可变 `pack_version` 并把 `active_version_id` 指向它（或仅登记 canary 白名单）。
- canary = `pack_activation(scope=workspace, canary=true)`：只有白名单 workspace 解析到新版本，其余用平台默认；v1 不做百分比。
- 回滚 = `activate` 旧版本（append 一条激活日志，版本行不动）。
- 发布门：`eval_receipt` 必须满足 `subject_kind=pack`、`subject_key`、`version_digest`= 本次 manifest 摘要、`eval_manifest_digest`= 当前评测清单摘要、`passed=true`、未过期（默认 30 天）。

## 8. Golden Set CI 与评测

### 8.1 清单与目录

- 技能评测：`apps/api/src/skills/{builtin,imported}/<pack_type>/<skill>/evals/evals.json`；Pack 评测：`apps/api/src/skills/packs/content/<type>/<pack-key>/evals/evals.json`。
- 格式沿用 GOV-TPS-003（`skill_name` + `evals[{id, prompt/input, expected_output, assertions[], files?}]`），断言收敛为闭集词汇（`equals`/`contains`/`regex`/`json_schema`/`enum`/`gte`/`lte`/`source_count_gte`/`no_vendor_marketing`/`tool_not_called`/`approval_required`），禁止自由 shell。
- 每个 skill/pack 至少 5 条必过用例；导入技能沿用上游 evals 作为扩展集（`upstreamEvalsPath`）。

### 8.2 两层执行

| 层 | 触发 | 跑什么 | 阻断 |
| --- | --- | --- | --- |
| CI 阻断层（零模型） | 每个 PR（路径触发） | 清单 schema/断言词汇校验；service 技能与 Pack 的确定性用例真实执行并精确断言；模型技能的渲染快照（system/user prompt 渲染结果与 fixture 比对）、工具白名单一致性、安全扫描、许可/NOTICE、catalog 快照 SHA | 失败即红 |
| 发布层（模型实测） | ops 触发（`/evals` 端点或脚本） | 模型技能：经 gateway 实跑 5 条必过 + 扩展集；Pack：在样本上下文渲染 + 规则解释器断言（无模型也可） | 无有效回执禁止 publish |

- 成本：单次模型评测按技能 ≤5 条必过 + 扩展集上限（默认 20 条）；回执记录 tokens/成本（µUSD）；单次运行成本上限 env 可调；模型层**永不进 CI**（无密钥）。
- 回执不可变；评测清单改动 = 新摘要 = 需重跑。

### 8.3 Catalog 与会话

- `pnpm packs:validate`（schema/语义/冲突/内容长度/许可）；`pnpm skills:evals:validate`（清单与断言词汇）；两者进 `gctl check`（或新 npm script + pre-push 路径）。
- 第三方目录一致性：`THIRD_PARTY_SKILLS.schema.json` 校验 + 快照 SHA-256 复核（复用 README §5 方法），CI 阻断层跑。

## 9. 闭环设计（§0.6 ②）

- **SoR**：Pack 目录/版本/激活 = 引擎 `pack_*` 表（平台级，ops 经 Pack Studio 写；内容包种子由 owner 连接）；技能注册沿用 S0 四表；策略解析事实 = `strategy_resolution_snapshot`（不可变）。
- **对外事件**：S1 **不新增 outbox 事件**（Pack/技能是平台配置，非租户业务事实）；评测与发布留痕在表内 + 结构化日志。M2 若需 Campaign 级策略事件，另立契约。
- **Tool Contract**：不新增对外工具；service 技能在引擎进程内执行（无出网、无工具）；model 技能仍经既有 ToolBroker（allowedTools 白名单）。
- **闭环位置**（计划 §17.6）：Understand/Qualify 之后、「Create/Research」前的策略层；`compliance.sanctions_screen` 衔接 Qualify 第五门；`quoting.incoterms_quote` 属 Create（Trade Ops M3+ 之前的 L1 建议）。
- **端到端演示（E2E-2，计划 §17.9）**：公司档案（含资料库事实）+ 制裁筛查（clear）+ 显式汇率与成本行 → `quoting.incoterms_quote` 产出一份带证据与公式版本的 L1 报价建议 → 人工确认；全程无对外单据、无发送。
- **负向测试**：service 技能声明工具被拒；未知 handler 被拒；Pack 冲突（低层放宽高层 forbid）发布被拒；无有效回执发布被拒；导入技能默认对租户不可用；`tenant-default: disabled` 时无覆盖不可解析；L1 技能输出 schema 中不存在 PI/单证字段（断言）。

## 10. 权限与合规

- RLS：7 张新表全部 FORCE RLS；平台目录跨空间可读、租户表按空间隔离；策略快照与回执 append-only。

## 14. 风险与开放问题

1. **S0 未发车**：本设计实现依赖线上 S0 表与 resolver；若发车前开工，只能写「未接线」的纯模块。建议 S1-1 可先做（零运行时依赖），S1-2 起等发车。

4. **评测成本与抖动**：模型评测有随机性与成本；回执绑定模型策略与清单摘要，重复运行需新回执；阈值与重试策略见 §8.2。

## 15. 联网研究（§0.6 ③，2026-11-08）

1. **Cedar / Amazon Verified Permissions（AWS）**：策略语言固定语义——默认拒绝、`forbid` 永远压过 `permit`；策略可版本化存储、支持 schema/语义校验与 **LOG_ONLY vs ACTIVE** 灰度模式（先用真实请求验证新策略版本再启用）。（[AWS AgentCore 文档](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/)、[Cedar 对比综述](https://casbin.apache.org/docs/casbin-vs-cedar/)）
   **借**：forbid 吸收 + 默认拒绝 + 发布前校验 + log-only 灰度；**建**：我们的优先级链比 Cedar 更细（合规/市场/行业），但用同一「高层不可被放宽」精神；**避**：不引入 Cedar/OPA 运行时（v1 规则是小集合，确定性解释器足够；Policy Engine 化留到 M2 评估）。
2. **promptfoo / 现代 LLM 评测 CI 实践（2026）**：分层评测（快速阻断层 / 发布层 / 定时漂移层）、确定性断言优先、模型评分克制且固定 grader、评测清单整体版本化（prompt/数据/断言/配置摘要）、退出码门禁、发布工件与成本核算。（[promptfoo evals skill](https://chromium.googlesource.com/external/github.com/promptfoo/promptfoo/+/ca8848c6ec054800d570cbd8a523d17e4c2e9d7a/.claude/skills/promptfoo-evals/SKILL.md)、[CI 实践综述](https://qajobfit.com/resources/building-evals-in-ci-with-promptfoo)）
   **借**：两层评测 + 清单摘要绑定 + 确定性优先 + 回执作为发布门；**避**：不在本仓引入 promptfoo 运行时/外部托管（无密钥、成本不可控；评测执行器自建在 Skill Runtime 内，S3 再评估集成）。

**结论（借/集/建/避）**：借 Cedar 的裁决与灰度语义、promptfoo 的评测分层与版本绑定；集无现成可集（均为外部运行时）；建 Pack 解释器/策略快照/评测执行器（复用现有 gateway 与纯函数）；避第二编排器、运行时策略引擎、CI 内模型调用。
