# Identity broker local execution implementation

Scope: implement and test the accepted one-shot broker direction locally. No credential creation, secret-store read, installed-root invocation, network call, materialization, retained DB operation or remote mutation is part of this phase. Root main remains owned by the queue task.

## Contracts and order

1. Add a stdlib-only bounded child-process primitive. It receives only a caller-reviewed executable/argv/environment and is not itself an authorization API. It uses shell=false, private cwd, stdout/stderr pipes, a shared byte budget, a monotonic deadline, a dedicated process group and group termination. It returns bounded stdout only on zero exit with empty stderr; all other outcomes contain only fixed codes. It never returns exception/cause/stderr/environment. Tests use temporary Node programs and no network.
2. Add a bounded inherited-pipe credential reader: FD>=3, a dedicated anonymous O_RDONLY|O_NONBLOCK FIFO supplied by the owner broker, at most8192bytes, EOF within5seconds and caller remaining deadline; reject empty, control/whitespace, non-ASCII and malformed values. The owner must not close/reuse the descriptor or change its flags while the reader is active; caller closes it afterward. The reader does not reopen the pipe via /proc/self/fd: that path blocked during a local no-EOF probe even with requested nonblocking flags. The reader validates the supplied nonblocking flag and reads that FD directly. It returns an in-memory buffer only to its caller; public errors contain fixed codes. Tests create anonymous pipes with synthetic credentials. File paths, gh configuration and fallback lookup are unsupported.
3. Define the broker environment adapter separately from controller ingress. Parent accepts an opaque handle; only the child GH process receives GH_TOKEN. GIT uses a reviewed config-env Authorization binding, never token-bearing argv/URL; system/global/local config, helpers, proxies, debug/trace, prompts and inherited headers are disabled. Git remote helper/dependency closure must be frozen before actual execution. Until that closure is complete, the adapter remains unavailable for real requests.
4. Bind the primitives to the fixed PROTECTED_MAIN_READBACK descriptors and source/tool/request/scope policy. A primitive PASS only proves the bounded process result. It cannot create a controller/materialization/ADMITTED receipt by itself. Shared-root CLI and journal/receipt producer follow only after their exact filesystem/executable closure is reviewed.
5. Run failure cases first, then success, coverage, repository governance/docs and independent review. Preserve previous unadmitted candidate commits. Do not push/merge or install to clear missing evidence.

## Local acceptance

Actual local child-process tests prove success, stderr/exit redaction, spawn failure, byte cap, timeout, descendant cleanup and invalid bounds. Actual anonymous-pipe tests prove exact credential bytes, missing/non-pipe FD, oversized/empty/invalid input, no EOF deadline and error redaction. No output artifact contains synthetic credential values except test source/input fixtures.

The process primitive is an implementation component, not an independently trusted executor. Its host/kernel, pinned executable behaviour and OS trust roots remain explicit assumptions; process groups alone do not contain an executable that deliberately escapes its group. No untrusted executable may enter the later broker.

## Local request journal component

`scripts/governance-organization-identity-readback-journal.mjs` implements only local durable deduplication before the installed controller exists. It accepts an existing normalized private directory owned by the current effective UID with mode 0700; it does not create a controller root. The future installed launcher must additionally enforce the exact approved root, operator, request authorization and source/tool closure before calling it.

The request ID determines one SHA-256 filename; the canonical record binds that ID to the exact request digest. An O_EXCL claim is persisted with file and directory fsync before returning an opaque, process-local claim capability. An existing claim always refuses execution, including after process exit, abandonment, digest mismatch or partial result. Caller must complete or abandon its capability in a finally path to close the held directory FD; process exit also closes it without deleting the durable claim.

The directory FD anchors record access across path replacement; root identity is checked before completion and after readback. Records are no-follow, nonblocking, regular, single-link, current-owner, mode 0600 and at most 4096 bytes. Completion accepts only a 40-hex head SHA and protected=true from an independently validated upstream observation. It uses exclusive creation and never overwrites an existing result. Readback verifies canonical bytes, request/claim/result bindings and filesystem identity, and synchronizes file and directory before returning. Disk failure or incomplete/tampered state remains HOLD. The trusted owner must not delete or mutate the journal; this mechanism cannot defend against malicious root or an operator deliberately replacing its records.

All results carry LOCAL_JOURNAL_ONLY and admissionGranted=false. Stored records contain no credential, arbitrary output, caller-supplied extra fields or authority claim. The journal neither validates remote observations nor signs an independent receipt. Actual controller and trusted receipt producer integration remain separate implementation work.
