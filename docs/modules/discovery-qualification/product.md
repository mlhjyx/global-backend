## 2. 模块定位与边界

### 2.1 用户与目标

- 服务用户：获客运营者、管理员。
- 要解决的问题：从「卖什么、卖给谁」到「哪些买家值得跟进」的完整判断链路过长、不可解释、失败后无法重试。
- 期望结果：ICP 可编辑、计划可确认、run 有进度且首批线索早出、线索可判断、交付包可下载、失败可重试。
- 在产品中的责任：模块 04 是获客主链路；止于不可变资格交付包（LeadQualifiedPackage）。

### 2.2 负责范围

| 范围 | 负责内容 | 完成条件 |
| --- | --- | --- |
| 当前设计覆盖 | ICP、资格规则与回测、查询计划（确认制）、发现 run、线索队列、评分、裁决、交付包、周报反馈、任务/重试（新） | 六步主链路可演示；失败可重试；首批线索 ≤10 分钟 |
| 后续范围 | 报价/PI/订单（Trade Ops，RL2+）、更多渠道（地图/海关） | 按渠道 backlog |

## 4. 模块流程

```text
公司档案（模块 02）→ ICP 向导（引用产品/目标市场）→ 激活
  → 生成查询计划 → 用户确认 → 执行 run（进度/首批线索）
  → 线索入队（待判断/值得跟进/暂不跟进/禁联）→ 背调（模块 03）
  → 裁决 accept/reject → 交付包 → 周报反馈 → 结果学习
  → 失败：同一任务下重试（新 run、新 Grant）
```

## 5. 子功能设计

### 5.1 ICP 与规则

- 引用档案的核心产品/目标市场生成初稿；可编辑行业/规模/排除条件/买家委员会；规则确定性可复算；回测展示历史命中。
- AC：无档案事实时提示补全；规则变更留痕。

### 5.2 查询计划（确认制）

- 生成 → 展示要点 → 确认 → 执行；未确认不得执行；同一计划同一 Grant 只能用一次。
- AC：未确认执行被拒；确认后自动开始。

### 5.3 Run 观察与性能

- 五段用户视图（搜索企业→收集核实→匹配判断→补充信号→汇总产出）；技术详情移入 ops；首批线索 ≤10 分钟可见；整轮 ≤30 分钟（25 家）；失败/部分如实展示。
- AC：阶段进度与预计时间；部分完成不掩盖已产出；失败有出路（调整 ICP/重试）。

### 5.4 线索与裁决

- 四队列（待判断/值得跟进/暂不跟进/禁联）；理由与证据首屏；accept 必须处理 409 阻断族；reject 必填原因码。
- AC：重复裁决幂等；reject 无原因码被拒。

### 5.5 任务与重试（新）

- 任务 = 一条挖掘需求；run = 执行尝试；失败重试 = 新 run（新授权、新预算）；旧 run 只读。
- AC：一键重试成功；同一任务多 run 历史可见；软删任务不删 run。

### 5.6 周报与反馈

- 周报 CSV（含 withheld 计数与决策人列）；在线反馈优先、CSV 兜底；反馈写 outcome。
- AC：反馈重传幂等；CSV 与在线反馈结果一致。
