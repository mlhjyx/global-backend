## 2. 模块定位与边界

### 2.1 用户与目标

- 服务用户：注册用户（老板/出海负责人）、工作空间管理员、成员、平台运营（只读/运营域，不属于本模块）。
- 要解决的问题：SaaS 必须以「注册用户 = 租户 = 工作空间」为隔离单元，任务、公司、资料都在空间内；当前注册与空间模型已具备，但缺少正式合同与引导流程。
- 期望结果：注册即创建独立空间；引导完成后公司档案可用；成员可邀请与分角色；所有业务数据按空间隔离；切换空间不丢上下文。
- 在整体产品中的责任：为模块 02–09 提供身份、空间与权限上下文；自身不承载业务数据。

### 2.2 负责范围

| 范围 | 本模块负责的内容 | 输出或完成条件 |
| --- | --- | --- |
| 当前设计覆盖 | 注册、登录/会话、工作空间（创建/改名/切换/退出）、成员邀请与角色、注册后引导、权限上下文（entitlements/allowedActions）、操作审计 | 新用户 10 分钟内完成注册→引导→邀请一名成员 |
| 后续范围 | 组织（Organization）、多空间高级管理、SSO/LDAP、计费与 Credits | 有真实客户需求并经产品负责人拍板 |

### 2.3 明确不做什么

| 明确不做什么 | 原因 | 由谁承接或如何处理 |
| --- | --- | --- |
| 工作空间物理删除 | 合规与审计要求；DSR 是唯一擦除路径 | 引擎 DSR/deletion workflow |
| 计费、订阅、Credits | 一期排除 | 模块 08/09 后期或独立模块 |
| 个人数据展示 | SD5 红线：`personal-data:read` 不进用户角色 | 管理员窄 scope 只用于决策人卡片 |

## 3. 术语与核心对象

| 术语 | 统一定义 | 本模块使用说明 |
| --- | --- | --- |
| User | 登录身份（邮箱+密码） | gain-saas 持有；引擎不存用户表 |
| Workspace | 租户隔离单元，id 即引擎 token 的 `workspace` claim | 注册即创建；存储/配额/审计/成员都以它为键 |
| Membership | User × Workspace，多对多，角色 admin/member | 一期 UI 只做切换器与邀请/移除 |
| Role | admin / member（一期两档） | 映射引擎 scopes；服务端强校验 |
| Entitlement | 工作空间能力开关（资料库/发现/ICP/联系人等） | 前端渲染 allowedActions，服务端仍强校验 |
| Onboarding | 注册后强制引导（公司/官网/行业/产品/目标市场） | 未完成前业务 API 被 OnboardingGuard 拦截 |

## 4. 模块流程

```text
注册（邮箱+密码+公司名+邀请码）
  → 创建 Workspace + admin Membership + WorkspaceRegistry + 默认 Entitlements
  → 强制引导向导（公司基本信息→核心产品 1–5→目标市场→官网→完成度）
  → 创建 CompanyProfile（模块 02）+ 触发公司理解（需执行授权）
  → 邀请成员/切换空间
  → 进入工作台（六步主链路）
```

## 5. 子功能设计

### 5.1 注册（A1）

- 字段：企业邮箱、密码、公司名称、邀请码（SD6）。
- 规则：一人一个主账号；注册即创建默认工作空间；公司名称作为空间显示名（D12 后从公司档案同步）。
- AC：重复邮箱返回 `EMAIL_TAKEN`；弱密码被拒（≥10 位、字母+数字）。

### 5.2 登录与会话（A2）

- 邮箱密码登录；HttpOnly `SameSite=Lax` 会话；短 TTL + 滑动续期；登出、改密。
- 规则：登录限流（同 IP+邮箱 5 次/15 分钟，落库实现，不依赖单进程内存）；`Secure` 在 TLS 路径启用。
- AC：会话失效后所有业务 API 401；改密吊销其他会话。

### 5.3 工作空间（A3）

- 名称可改；一个账号可属多个空间并切换；侧栏头部提供切换器（带头像/色块区分），不做整页刷新。
- 规则：最后一名成员不能退出（`LAST_MEMBER`）；不做物理删除。
- AC：切换空间后公司档案、任务、线索均切换到对应空间；跨空间访问 404。

### 5.4 成员管理（A4）

- 邀请（复制链接/邮件链接）、移除、角色变更、成员列表。
- 规则：仅 admin 可邀请/移除/改角色；成员邮箱仅 admin 可见（前端隐藏 + 服务端强校验）。
- AC：member 调用 admin 端点 403；邀请接受后按角色获得权限。

### 5.5 注册后引导（D10）

- 注册完成立即进入向导；可暂存；填写官网/行业/核心产品/目标市场/业务邮箱；完成后创建公司档案并触发理解。
- 规则：未完成引导前，除认证/工作空间/引导/通知外的租户 API 一律 403（OnboardingGuard）。
- AC：向导可暂存、可跳过官网（D17）；完成后档案完整度 100%；无官网公司也能建档。

### 5.6 权限上下文与审计（A7）

- `GET /api/workspace/context` 返回 entitlements + allowedActions；前端只渲染 allowedActions。
- 审计：成员/角色/邀请/空间变更全量留痕，记录对象身份（不含敏感值）。
- AC：未知 action 隐藏/禁用并给解释；审计可按人/对象检索。

## 6. 与其他模块的关系

- 向模块 02–09 提供空间上下文与权限；不复制业务对象。
- 与引擎的接口：JWT（`workspace` claim）+ scopes；引擎只验签，不存用户。

## 7. 验收标准

| 编号 | 验收 |
| --- | --- |
| AC-AW-1 | 新用户注册 → 引导 → 邀请成员 → member 以成员权限操作，10 分钟内完成 |
| AC-AW-2 | 未完成引导时直接调用业务 API 被 403 |
| AC-AW-3 | 跨空间访问返回 404，不泄露存在性 |
| AC-AW-4 | 成员邮箱仅 admin 可见；member 调用 admin 端点 403 |
| AC-AW-5 | 切换空间后所有页面数据随空间切换 |
